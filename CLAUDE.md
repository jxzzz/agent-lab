# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Workspace layout

This is NOT a single project — it is a multi-project workspace (no git at the root). Each subdirectory is a self-contained project with its own dependencies, `.env`, and entry points. Always `cd` into the relevant subproject before running anything.

| Directory | Stack | What it is |
|---|---|---|
| `fundamentals/` | Python (`.venv/` inside) | Standalone learning scripts (LLM calls, function calling, LangGraph basics) |
| `ai-sdk-lab/` | TypeScript, pnpm + tsx | AI SDK agent exercises split into `task-1/2/3` |
| `project-1-customer-agent/` | Python, LangGraph + DeepSeek + SQLite | 客服数据 Agent：自然语言查订单/销售/库存，退款与提醒，人工确认 |
| `project-2-knowledge-agent/` | Python, LangGraph + RAG | 客服知识库 Agent：文档切分 → embedding → 向量检索 → 带来源回答 |
| `project-3-report-agent/` | Python, LangGraph, multi-agent | 多 Agent 数据分析报告：planner → data → writer → reviewer → 人工确认 |

All LLM projects use the DeepSeek API (OpenAI-compatible) via per-project `.env` files. `.env` files contain real API keys — never print, quote, or commit their contents.

## Commands

### ai-sdk-lab (from `ai-sdk-lab/`)
```bash
pnpm install
pnpm dev            # runs task-1/index.ts
pnpm dev:umbrella   # task-2
pnpm dev:voice      # task-3/server.ts
```
Scripts use `tsx --env-file=.env`, so `.env` must exist.

### Python projects
Every Python project has its own `.venv/` (system Python is kept clean and has no packages). Run tests from inside the project directory:

```bash
.venv/bin/python -m pytest tests -q           # all projects
.venv/bin/python -m pytest tests/test_api.py -q      # single file
.venv/bin/python -m pytest tests/test_api.py::test_name -q   # single test
```

### Running the agents
```bash
# project-1: seed DB first, then chat
python create_sample_db.py && python agent.py

# project-2: rebuild index after changing docs/, then API
python chunk_docs.py && python build_vector_index.py
uvicorn api:app

# project-3
python cli.py            # CLI with human confirmation gate
uvicorn api:app          # HTTP API (also: python evaluate.py for the eval set)
```

## Architecture notes

- **LangGraph pattern shared by projects 1–3**: a state object flows through graph nodes; conditional edges route after each node (tool calls → tools node → agent; review fail → rewrite, capped at 2 rounds in project-3). Changing one node's state fields requires checking `state.py` / the graph wiring, not just the node.
- **project-2 RAG pipeline is file-based**: `chunks.jsonl` and `vector_index.json` are build artifacts generated by `chunk_docs.py` → `build_vector_index.py`. Editing docs or chunking logic means re-running both, otherwise retrieval silently serves stale data.
- **project-3 SQLite is deliberately read-only** (`PRAGMA query_only`, SELECT-only, no semicolons) and its reports are hard-validated: every data claim in a report must cite a real executed query. Don't loosen these guards when debugging.
- Both project-2 and project-3 have `eval_questions.jsonl` eval sets and are tested with real model calls — a failing eval test may be an API/quota issue, not a code bug.
